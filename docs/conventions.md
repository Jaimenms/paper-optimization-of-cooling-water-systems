# Conventions of the paper-reproduction series

Three repositories reimplement, in Python, the models of published papers by J. N. M. de Souza
and co-authors and reproduce their tables and figures:

| Repository | Package | Paper(s) |
|---|---|---|
| `paper-optimization-of-gas-lift-systems` | `gaslift` | de Souza, de Medeiros, Costa & Nunes, *J. Pet. Sci. Eng.* 72 (2010) 277–289 |
| `paper-hydraulic-design-optimization` | `cwnet` | Souza, Ventin, Tavares & Costa, *Chem. Eng. Comm.* 201 (2014) 1054–1076; Costa, Tonassi & Souza, *Chem. Eng. Trans.* 52 (2016) |
| `paper-optimization-of-cooling-water-systems` | `coolingnet` | Souza, Levy & Costa, *Appl. Therm. Eng.* 128 (2018) 1531–1542 |

The three repositories follow the same layout, commands, documentation set and notebook
structure so that they can be used as a series.

## Layout

```
README.md  CITATION.cff  LICENSE  CLAUDE.md  Makefile  pyproject.toml  uv.lock  .python-version  .gitignore
src/<package>/    the Python package (src layout, hatchling, uv-managed, Python 3.12)
cases/            input data of the paper case studies (YAML/JSON), fully editable
data/reference/   published values and original-code results used by the tests and by `eval`
notebooks/        executed notebooks NN_<slug>.ipynb, generated by scripts/build_notebooks.py
scripts/          build_notebooks.py and other maintenance scripts
tests/            pytest suite (fast by default; long runs carry the `slow` marker)
docs/             formulation.md, architecture.md, reproduction.md, errata.md, conventions.md, pt/
legacy/           original code that produced the published results (MATLAB, Scilab, GAMS/R), read-only
results/          outputs of `make run` and `make eval` (not versioned unless runs are expensive)
figures/          figures and tables exported by `make figures`
```

Manuscripts, PDFs, reviews, drafts and any other material of the papers are never kept in the
repository (nor in its history); they stay outside, in `~/code/personal/paper-raw-material/<repository>/`.

## Commands (`Makefile`, identical targets in the three repositories)

| Target | Action |
|---|---|
| `make setup` | create `.venv` with uv and install the package with all extras |
| `make lint` / `make format` | ruff check / ruff format |
| `make test` | fast tests (seconds) |
| `make test-all` | all tests, including the `slow` ones |
| `make run` | run every case study of the paper(s) and write `results/` |
| `make eval` | compare the results with the published values and write `results/eval/` (markdown + CSV) |
| `make figures` | export the figures and tables of the paper(s) to `figures/` |
| `make notebooks` | regenerate and execute the notebooks |
| `make clean` | remove caches and build artefacts |

## Command line (`<package>` console script, same verbs)

| Verb | Action |
|---|---|
| `<package> info` | paper reference(s), available cases, package version |
| `<package> validate <case>` | check a case file (schema, topology) |
| `<package> run [<case>] [--out results/]` | run the study of one case (default: every paper case) |
| `<package> eval [--out results/eval]` | reproduce the published tables and report the deviations |
| `<package> figures [--out figures/]` | export the figures and tables of the paper(s) |

Additional verbs are allowed (`simulate`, `convert-legacy`, `export-config`, ...).

## README (English, with a "Resumo em português" section)

1. Title: `<package> — <one-line description>`.
2. Reference block (quote) per paper: authors, **title**, journal, volume (issue), pages, year, DOI.
3. What the package does / what is reproduced (status table per table and figure).
4. Quick start (`make` targets and CLI verbs).
5. Notebooks table (notebook → paper items).
6. Configuring a case.
7. Layout (file tree, same shape as above).
8. Documents (links to `docs/`).
9. Resumo em português.
10. License (MIT for the code).

## Documents (`docs/`)

| File | Content | Language |
|---|---|---|
| `formulation.md` | equation ↔ code map | English |
| `architecture.md` | package layout and design decisions | English |
| `reproduction.md` | reproduction status per table/figure, discrepancies that are not paper errors, notes on the original code | English |
| `errata.md` | formal errata, one section per paper, with location (page/table/equation), published text, correction, impact | English |
| `conventions.md` | this file | English |
| `pt/*.md` | Portuguese working notes (optional) | Portuguese |

## Notebooks

`00_` configuration tutorial (optional), then one notebook per case study / paper topic in the
order of the paper, extras last. Every table or figure cell names the paper item it reproduces
and, where the paper prints values, shows them side by side with the recomputed ones.

## Tests and code

* `pytest` runs in under a minute by default; regression tests compare with the published tables.
* ruff (line length 100), SI units internally, pydantic or dataclasses for the data model,
  the original-code behaviour as default with the paper's variants as options when they differ.
